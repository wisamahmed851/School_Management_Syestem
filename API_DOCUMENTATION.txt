================================================================================
SCHOOL MANAGEMENT SYSTEM — API DOCUMENTATION
================================================================================

PROJECT OVERVIEW
Tech Stack: NestJS + TypeORM + MySQL
Base URL: {{base_url}} (default: http://localhost:3000)

This system provides a full-featured school management backend. It supports:
  • Admin authentication and role/permission-based access control
  • Management of admins, users (teachers & parents), roles, and permissions
  • Teacher, guardian, student, class, and subject management
  • Class-subject-teacher mapping
  • Attendance tracking (by admin or teacher)
  • Assignment creation, submission, and grading
  • Exam scheduling and result entry
  • A parent portal for viewing children, attendance, and assignments

--------------------------------------------------------------------------------
AUTHENTICATION
--------------------------------------------------------------------------------

TOKEN TYPES
-----------
1. admin_token
   Issued at: POST /admin/login
   Used by:   Admin users to access all /admin/* management endpoints.

2. teacher_token
   Issued at: POST /user/login  (same endpoint used by parents)
   Used by:   Teacher users to access /user/teacher/* endpoints.
   Requires:  The User account must have the "teacher" role assigned.

3. parent_token
   Issued at: POST /user/login  (same endpoint used by teachers)
   Used by:   Guardian/parent users to access /user/parent/* endpoints.
   Requires:  The User account must have the "parent" role assigned.

HOW TO SEND A TOKEN
-------------------
Include the token in every protected request header:
  Authorization: Bearer <token>

PUBLIC ROUTES (no token required)
----------------------------------
  POST /admin/login
  POST /user/login
  POST /user/register
  POST /user/refresh-token

IMPORTANT: Teachers use the SAME /user/login endpoint as parents.
The system differentiates between the two by the roles assigned to the
User account. A teacher must have the "teacher" role assigned via
POST /admin/roles-assigning-user/store.

Base path: /user
Controller: UserAuthController

────────────────────────────────────────────────────────────────────────────────
20.1. POST /user/login
Log in as a teacher (or parent) and receive a JWT access token.

Guard:        None — public route
Path Params:  None
Query Params: None

Request Body:
{
  "email": "bilal.ahmed@school.com",
  "password": "Teacher@123"
}

Success Response (HTTP 200):
{
  "success": true,
  "message": "Login successful",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": {
      "id": 10,
      "name": "Mr. Bilal Ahmed",
      "email": "bilal.ahmed@school.com",
      "roles": ["teacher"]
    }
  }
}

Error Responses:
  401: { "statusCode": 401, "message": "Invalid email or password" }
  400: { "statusCode": 400, "message": ["email must be an email"] }

================================================================================
SECTION 23: PARENT — AUTHENTICATION
================================================================================

IMPORTANT: Parents use the SAME /user/login endpoint as teachers.
The system differentiates between the two by the roles assigned to the
User account. A parent must have the "parent" role assigned via
POST /admin/roles-assigning-user/store.

All user authentication endpoints (login, register, profile, update-profile,
change-password, logout, refresh-token) are shared between teachers and parents.
See SECTION 20 for full details of each endpoint.

Summary of shared endpoints:
  POST   /user/login            — obtain access_token + refresh_token
  POST   /user/refresh-token    — exchange refresh token for new access token
  POST   /user/register         — self-register a new user account
  GET    /user/profile          — get own profile
  PUT    /user/update-profile   — update own profile (multipart/form-data)
  POST   /user/change-password  — change own password
  POST   /user/logout           — invalidate session
